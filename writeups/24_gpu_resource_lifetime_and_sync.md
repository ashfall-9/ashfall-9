# 24 — GPU Resource Lifetime and Synchronization Contract

## Goal

The renderer must make GPU lifetime and synchronization visible enough that descriptor indexing, async compute, capture readbacks, and future ray tracing can be added without hidden hazards.

## Core identifiers

```rust
#[repr(transparent)]
#[derive(Clone, Copy, Debug, Hash, PartialEq, Eq, PartialOrd, Ord)]
pub struct SubmissionId(pub u64);

#[repr(transparent)]
#[derive(Clone, Copy, Debug, Hash, PartialEq, Eq, PartialOrd, Ord)]
pub struct TimelineValue(pub u64);

#[repr(transparent)]
#[derive(Clone, Copy, Debug, Hash, PartialEq, Eq, PartialOrd, Ord)]
pub struct DescriptorEpoch(pub u64);

#[repr(transparent)]
#[derive(Clone, Copy, Debug, Hash, PartialEq, Eq, PartialOrd, Ord)]
pub struct ResourceGeneration(pub u32);
```

Every GPU resource handle should include an index and generation so stale handles are detectable in debug/eval builds.

## Resource record

```rust
pub struct GpuResourceRecord {
    pub id: GpuResourceId,
    pub generation: ResourceGeneration,
    pub kind: GpuResourceKind,
    pub owner: ResourceOwner,
    pub created_frame: u64,
    pub last_used_submission: Option<SubmissionId>,
    pub last_known_timeline: Option<TimelineValue>,
    pub descriptor_epoch: Option<DescriptorEpoch>,
    pub debug_name: String,
}
```

## Lifetime rule

A GPU resource may be destroyed only when all of these are true:

```text
- no live CPU handle points to its generation
- no descriptor table entry visible to pending GPU work points to it
- no submitted command buffer can access it
- no capture/readback job references it
- no acceleration structure build/update references it
```

Use a deferred-destruction queue:

```text
resource_retirement_queue.push(resource, retire_after_timeline_value)
```

The queue is drained only after the relevant timeline value or fence has completed.

## Descriptor epoch rule

Descriptor writes must be versioned.

```text
- every descriptor table update increments or records a DescriptorEpoch
- every submission records the descriptor epoch range it may access
- resources referenced by an epoch remain alive until all submissions that can access that epoch complete
- update-after-bind is permitted only for bindings and devices that explicitly support it
- partially-bound arrays require shader-side validity rules and debug fallback descriptors
```

Do not update a descriptor merely because the CPU no longer intends to use it. Update only when pending GPU work cannot access the old value or the binding's update-after-bind rules and synchronization have been satisfied.

## Render graph synchronization rule

The render graph owns resource usage declarations.

Each pass declares:

```text
- queue class
- resource reads
- resource writes
- access kind
- expected layout/state for images
- whether queue-family ownership transfer is needed
```

The graph compiler produces:

```text
- image layout transitions
- buffer/image memory barriers
- queue ownership transfers
- semaphore waits/signals between queues
- timestamp scopes
- hazard diagnostics in debug/eval builds
```

Manual barriers outside the graph are allowed only in backend escape hatches and must be documented.

## Queue policy

Initial renderer:

```text
- graphics queue does most work
- transfer queue optional for uploads
- async compute disabled by default
```

Later renderer:

```text
- async compute only for passes with measured overlap benefit
- queue ownership transfers must be generated by render graph
- telemetry must show queue timing and bubbles
```

Do not add async compute because it appears theoretically faster. Add it only when captures show a real benefit on the hardware profile.

## Readback and capture rule

Captures are asynchronous jobs.

```text
1. render graph copies image/buffer data to staging resources
2. submission records the timeline value required for safe CPU mapping
3. capture worker maps only after the timeline completes
4. capture worker writes PNG/EXR/JSON artifacts
5. eval_lab consumes the artifact paths, not live GPU memory
```

Normal gameplay frames must never block on capture readback.

## Validation modes

```text
dev_debug:
  enable validation layers, synchronization validation, debug names, resource-handle generation checks

dev_profile:
  validation optional, timestamps mandatory, profiler labels mandatory

eval:
  deterministic seeds, validation log captured, debug AOVs enabled, no shader hot reload

release:
  validation disabled, assertions reduced, telemetry sampled, no CPU readback unless explicitly requested
```

## Merge gate for resource-binding changes

Any change to descriptors, resource allocation, barriers, or queue scheduling must include:

```text
- before/after RenderDoc or profiler capture note
- validation-layer result
- smoke test for resize/swapchain recreation if presentation is touched
- resource-retirement test if descriptors/resources are touched
- eval artifact diff if a visual pass changes
```

## V4 shader ABI dependency

Resource lifetime and descriptor epochs are inseparable from shader ABI stability. A descriptor index stored in a GPU-packed struct is only valid if:

```text
- the packed struct layout matches shader expectations
- the descriptor table epoch is recorded with the submission
- the referenced resource remains alive until that submission completes
- invalid indices map to explicit fallback resources or fail validation in debug/eval builds
```

See `40_shader_abi_and_gpu_data_layout.md` for packed struct and shader reflection requirements.
